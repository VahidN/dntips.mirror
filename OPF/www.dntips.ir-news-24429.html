‫مهاجرت بک‌اند .NET قدیمی به GraphQL: تجربه‌ی بقا با بیش از ۲۰ دامنه و ۱۰۰ جدول SQL


نویسنده: راویAI
تاریخ: ۱۴۰۴/۱۲/۰۹ ۰۹:۰۲
آدرس: www.dntips.ir
در این مقاله، نحوه‌ی مهاجرت یک بک‌اند .NET 6 سرورلس بزرگ به GraphQL به صورت تدریجی بررسی می‌شود. این رویکرد شامل استفاده از Next.js برای رندرینگ مدرن React، GraphQL برای پرس‌وجوی انعطاف‌پذیر داده‌ها، یک مخزن مشترک (monorepo) برای هماهنگی کد در بین تیم‌ها، و اجزای وب برای رابط کاربری قابل استفاده مجدد است. هدف اصلی، اجتناب از بازنویسی کامل و پرخطر و در عین حال امکان تحویل مداوم ویژگی‌های جدید است. بک‌اند قدیمی شامل بیش از ۳۵ گروه وظیفه‌محور، صدها تابع Lambda و بیش از ۱۰۰ جدول SQL است. هر تابع Lambda اغلب دسترسی به پایگاه داده، منطق تجاری و پاسخ‌های API را ترکیب می‌کند که باعث وابستگی شدید اجزا می‌شود. این وابستگی‌ها و همچنین الگوهای قدیمی مانند ترکیب پرس‌وجوهای LINQ با رویه‌های ذخیره شده، نگهداری، تست و کنترل نسخه را دشوار می‌کند. برای مقابله با این چالش‌ها، از یک رویکرد تدریجی با استفاده از یک مخزن مشترک، GraphQL و کمک هوش مصنوعی استفاده شده است. این شامل جداسازی منطق، به‌روزرسانی سیستم‌ها به صورت تدریجی و کاهش خطر معرفی خطاها است. AWS Lambda برای اجرای صدها تابع در چندین دامنه استفاده می‌شود، API Gateway نقاط پایانی REST را با مجوزهای JWT و Cognito ارائه می‌دهد و S3 برای ذخیره الگوها، آپلودها و مصنوعات استقرار استفاده می‌شود. تیم توسعه‌دهندگان از هوش مصنوعی برای درک کدهای قدیمی و پیچیده استفاده کرده‌اند. این امر به آن‌ها کمک می‌کند تا وابستگی‌ها را شناسایی کرده و فرآیند مهاجرت را تسریع بخشند. استفاده از GraphQL امکان پرس‌وجوهای انعطاف‌پذیر داده‌ها را فراهم می‌کند و به تیم‌ها اجازه می‌دهد تا رابط‌های کاربری مختلفی را با داده‌های مورد نیاز خود ایجاد کنند. در نهایت، این رویکرد تدریجی به تیم اجازه می‌دهد تا بک‌اند .NET خود را به GraphQL مهاجرت دهد در حالی که از اختلال در کسب و کار جلوگیری می‌کند و امکان تحویل مداوم ویژگی‌های جدید را فراهم می‌کند. این روش برای پروژه‌های بزرگ و پیچیده که نیاز به مدرن‌سازی دارند، یک راهکار عملی و کارآمد است.
